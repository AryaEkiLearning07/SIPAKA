AI menjadi pelaksana teknis, sedangkan arsitektur, aturan domain, kontrak data, dan 
standar kualitas harus ditentukan terlebih dahulu olehmu bersama ahli hukum.

Next.js menggunakan struktur routing berbasis folder, sehingga halaman reader, compare, dan admin 
dapat dipisahkan secara konsisten. NestJS mengorganisasi aplikasi menggunakan module, 
controller, dan provider, sehingga modular monolith tetap dapat dikembangkan tanpa langsung 
beralih ke microservices.
Sumber resmi: Next.js App Router Documentation; NestJS Modules Documentation.
Stack yang digunakan
Komponen Pilihan
Frontend Next.js + TypeScript
Backend NestJS + TypeScript
Database PostgreSQL
ORM Prisma
API REST + OpenAPI
Penyimpanan dokumen S3-compatible storage
Testing backend Jest
Testing frontend/E2E Playwright
Local infrastructure Docker Compose
Package manager pnpm
Repository GitHub private repository
Prisma memberikan akses database yang type-safe dan mencatat perubahan skema melalui 
migration history. File migrasi SQL tetap dapat disesuaikan ketika dibutuhkan fitur PostgreSQL yang 
lebih spesifik.
Sumber resmi: Prisma Migrate Documentation.

5. Empat Lapisan Data
Fondasi database sebaiknya dibagi menjadi empat lapisan.
Lapisan 1 - Sumber resmi
Menyimpan dokumen yang diperoleh dari sumber resmi.
SourceDocument
├── URL sumber
├── Institusi penerbit
├── File PDF
├── Hash file
├── Tanggal diperoleh
├── Nomor Lembaran Negara
└── Status pemeriksaan
Dokumen ini bersifat immutable. Jika ditemukan file yang lebih benar, file lama tidak ditimpa. Sistem 
menambahkan rekaman sumber baru.

perubahan yang telah disetujui.

├── memiliki REVIEW_RECORD

Tanggal yang perlu dibedakan
Jangan hanya memiliki satu kolom tanggal.
enacted_at       = tanggal ditetapkan
promulgated_at   = tanggal diundangkan
effective_from   = mulai mempunyai akibat hukum
recorded_at      = dimasukkan ke platform
reviewed_at      = diperiksa reviewer
published_at     = ditampilkan kepada pengguna
Pemisahan ini penting karena waktu berlakunya norma berbeda dari waktu platform memperoleh atau 
memublikasikan data.
7. Operasi Perubahan MVP
Database boleh dirancang untuk banyak jenis perubahan, tetapi mesin pertama hanya perlu 
mengimplementasikan:
ADD_PROVISION
REPLACE_PROVISION
REPEAL_PROVISION
Setelah ketiganya stabil, tambahkan:
INSERT_BEFORE
INSERT_AFTER
REPLACE_TEXT
DELETE_TEXT
RENUMBER
MOVE
PARTIAL_REPEAL
Jangan langsung membuat mesin generik untuk semua kemungkinan. Buat antarmukanya fleksibel, 
tetapi implementasinya bertahap.

12. Strategi Vibe Coding
Aturan utama
Satu issue, satu tujuan, satu perubahan kecil, satu rangkaian pengujian.
Jangan memberikan prompt:
“Buatkan backend version control undang-undang secara lengkap.”
Gunakan prompt seperti:
Tujuan:
Tambahkan endpoint GET /api/v1/provisions/:id/history.
Konteks:
Provision memiliki banyak provision revisions dan change operations.
File yang boleh diubah:
- apps/api/src/provisions/*
- packages/shared-types/*
- apps/api/test/provisions/*
Di luar cakupan:
- Jangan mengubah schema database.
- Jangan mengubah authentication.
- Jangan melakukan refactor module lain.
Kriteria penerimaan:
1. Mengembalikan seluruh revisi secara kronologis.
2. Menampilkan sumber perubahan.
3. Mengembalikan 404 jika provision tidak ditemukan.
4. Memiliki unit dan integration test.
5. OpenAPI diperbarui.
Sebelum mengimplementasikan:
Jelaskan rencana perubahan dan file yang akan disentuh.

16. Strategi Pengujian
Unit test
Menguji aturan kecil:
• Mengurutkan perubahan berdasarkan effective_from
• Menentukan versi aktif pada tanggal tertentu
• Menolak publication dari change set yang belum disetujui
• Menolak perubahan target yang tidak ditemukan
Golden test
Ini sangat penting untuk version engine.
Simpan contoh input:
tests/fixtures/sample-law/
├── original.json
├── amendment-1.json
└── amendment-2.json
Simpan hasil yang diharapkan:
tests/golden/sample-law/
├── version-1.json
├── version-2.json
└── version-3.json
Setiap perubahan kode version engine harus menghasilkan output yang sama. Jika berubah, 
developer wajib menjelaskan alasannya.
Integration test
• Membuat instrument
• Menambahkan provision
• Membuat change set
• Mengajukan review
• Menyetujui review
• Memublikasikan versi
